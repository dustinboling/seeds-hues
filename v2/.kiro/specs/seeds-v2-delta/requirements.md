# seeds-v2-delta — Requirements

Source of truth: `~/workspace/seeds-hues/SPEC-CANONICAL.md` (adopted 2026-11-16) and
`~/workspace/seeds-hues/DELTA-PLAN-DEC16.md` §(b). Where this delta conflicts with the
original seeds-v2 spec, THIS delta wins. Everything not mentioned here stays as built.

## R1 — Prices are stored, never shown (canonical decision 3/23)
- No price may appear in any HTML page, JSON-LD block, or public `/api/v1` response.
- Price storage (`listing_packet_sizes.price_cents`, `price_history`) is unchanged.
- Remove the `price-asc`/`price-desc` API sorts. Remove price rendering components
  from pages (packet table shows no prices; the listing row follows R6).
- Guardrail/acceptance tests must FLIP: they now assert price absence.

## R2 — Launch sellers are the six exemplars (decision 25) — DATA ALREADY DONE
- `seed-data/catalog.json` has already been regenerated by Hue: 19 plants / 68
  varieties / **6 sellers / 17 listings**. Do not change the dataset or the generator.
- Seller records now carry: eligibility, approvedAt (2026-11-15), termsReviewedAt
  (null), approvalNote, domain, crawlPolicy, claimStatus, country, region, shipsTo,
  isSiteOwner. The importer must map all of them.
- Varieties now carry `series` (name or null) — only "Dearest" in this dataset.

## R3 — Singular public URLs (canonical §2 slugs)
- Canonical web routes: `/variety`, `/variety/[slug]`, `/seller`, `/seller/[slug]`,
  `/crop`, `/crop/[slug]`, `/series/[slug]`. Slug VALUES do not change.
- 308 redirects: `/varieties`→`/variety`, `/varieties/[slug]`→`/variety/[slug]`,
  `/sellers`→`/seller`, `/sellers/[slug]`→`/seller/[slug]`, `/plants`→`/crop`,
  `/plants/[slug]`→`/crop/[slug]`, `/categories`→`/crop`, `/categories/[slug]`→`/crop`.
  Legacy `?v=`/`?s=` handling retargets to the singular routes.
- Sitemap, llms.txt, robots.txt, internal links, tab bar, OG image routes and
  metadata builders all use the singular scheme.
- API naming follows the canonical spec: `/api/v1/crops` replaces `/api/v1/plants`
  (the API was never deployed; no compatibility shim).

## R4 — Structured data exactly per canonical §5 table
- Home: WebSite + Organization. Crop/series: ItemList. Seller: Organization +
  ItemList. Variety: BreadcrumbList + ItemList of sellers.
- **No Product / AggregateOffer / Offer / AggregateRating / Review / FAQPage /
  priceValidUntil anywhere.** (Removes the current conditional Product block.)

## R5 — Index rule (canonical §5, decision 8) — REPLACES the ≥3-facts rule
- A variety page is indexable iff it has ≥ 1 published listing OR ≥ 150 words of own
  notes (description + sowing_notes word count). Otherwise `noindex, follow` and
  excluded from the sitemap. The importer recomputes `indexable` with this rule.

## R6 — Variety page + listings (canonical stories 2–3)
- Top: an answer sentence built only from data ("As of {date}, N small farms list
  {Variety}: {seller names}." / zero-seller: "No small farm found selling this yet").
- Facts block prints "Unknown" for unknown values (color_family, pollination,
  height, days to bloom).
- Each listing row: seller name (link to /seller/[slug]), region, availability label
  (In stock / Sold out / Preorder / Shop closed / Unknown), "Last checked {date}",
  a source link (the provenance source URL), and a Shop button → `/go/{listing_id}`.
  In-stock listings sort first. Outbound links carry `rel="nofollow noopener"`.
- "Not yet rated" stays. "Also sold as" lists aliases. "Report a problem" links to
  `/report?variety={slug}`.

## R7 — /go/{listing_id} (canonical §3/§5)
- GET route outside the API. Looks up the listing; 404 if unknown/unpublished;
  410 if the seller was removed.
- Records a `click_events` row: at, listing_id, variety_id, seller_id,
  availability_at_click, page_type (derived from Referer path), referrer_host,
  client (X-Client header or UA family), visitor_day_hash (salted SHA-256 of
  salt|IP|UTC-date; the IP itself is NEVER stored), is_bot (UA heuristic).
- Responds 302 to the listing's product URL (fallback: seller homepage), appending
  `utm_source=seedfinder&utm_medium=referral` while preserving any existing query
  string (do not overwrite an existing utm_source). `Cache-Control: no-store`.

## R8 — Reports, claims, removal (canonical §2, story 6)
- `/report` page: one form, three intents (correct / claim / remove), target
  (variety or seller slug, prefilled from query params), message, contact email.
- `POST /api/v1/reports` (public): Zod-validated; stores a `reports` row AND a
  `review_items` row (type removal / seller_correction) so it lands in the queue.
  Turnstile: verify the token against siteverify ONLY when `TURNSTILE_SECRET_KEY`
  is configured; otherwise accept and mark the row `turnstile: "not_configured"`.
  Rate limit 3/min/IP.
- Admin removal of a seller: eligibility → `removed_by_request`, all listings →
  status `removed`, seller page responds **410**, domain inserted into
  `blocked_domains`, seller excluded from API lists/sitemap/search.

## R9 — Sync (canonical §3)
- `GET /api/v1/sync/snapshot`: JSON `{catalog_seq, schema_version, generated_at,
  crops, series, varieties, names, sellers, listings}` in public shapes (no prices;
  approved sellers only; published listings only; all non-deleted varieties).
  ETag derived from catalog_seq.
- `GET /api/v1/sync/changes?since={seq}&limit=`: `{upserts: {crops, series,
  varieties, sellers, listings}, deletes: [{type, id, merged_into?}], next_seq,
  has_more}` driven by `updated_seq` + `deleted_at` tombstones. `since` in the
  future → 400; `since` < 0 → 410 with code `resync_required`.
- KEEP the existing `catalog/version` and `catalog/snapshot/{version}.sqlite`
  endpoints untouched (the .sqlite remains the Phase 2 replica vehicle).

## R10 — Ingest API (canonical §3/§4) — server side only; NO crawling
- Auth: `Authorization: Bearer` key with scope `ingest`. Keys are SHA-256 hashes in
  `api_keys` (scopes JSON, last_used_at, revoked_at). `scripts/create-api-key.ts`
  mints a key, stores only the hash, prints the token once.
- `POST /ingest/jobs/lease` {count, agent?, model?, prompt_version?} → leases up to
  N queued `crawl_jobs` (lease_expires_at = now + 15 min; expired leases return to
  queued); creates an `agent_runs` row when agent info is given.
- `POST /ingest/jobs/{id}/complete` / `/fail` (fail: attempts++, next_run_at backoff).
- `POST /ingest/sources` {url, fetched_at, http_status, content_text, robots_allowed,
  kind} → SHA-256 content hash, snapshot stored in the SNAPSHOTS R2 bucket at
  `fetch/{hash}.txt`, `fetch_sources` row; idempotent on (url, content_hash).
- `POST /ingest/observations` {observations: […]} (max 100), each shaped like the
  canonical extraction schema `listing_observation/1` (seller_id as slug or id,
  source_id, product{url, external_product_id, variant_key, title_raw, is_seed,
  crop, variety_name, availability — each extraction a {value, evidence} pair},
  match{variety_id?, method, confidence, candidates?}). Per-item results.
  **Validation, in this exact order** (canonical §4): (1) schema + enums legal;
  (2) seller exists, is approved, crawl policy allows the fetch (`opted_out` →
  reject; `manual_only` → reject unless the fetch source kind is `human`);
  (3) product URL host == seller domain and domain not in `blocked_domains`;
  (4) source exists and was fetched within 7 days; (5) **every non-"unknown" value's
  evidence quote is found verbatim in the stored snapshot** — one miss rejects the
  observation with reason `evidence_not_found`; (6) upsert key (seller, URL, variant).
  Publishing: exact/synonym match (match.variety_id set and the extracted name
  normalizes to the variety's primary name or a known alias) on an approved seller
  with verified evidence → publish immediately (create/update listing, provenance
  copied, `listing_events` row on state change). Anything else → `review_items`
  (grouped by normalized name). Model matches NEVER auto-publish.
- `POST /ingest/seller-candidates` {name, website_url, evidence, source_id?} →
  `review_items` type seller_candidate. Never auto-approved.
- `GET /ingest/match-context?crop={slug}` → the crop's varieties with id, slug,
  primary name and aliases, for agent-side matching.
- Every ingest POST honours `Idempotency-Key` (stored response replay).

## R11 — Admin API (canonical §3)
- Auth: Bearer key with scope `admin`.
- `GET /admin/review?type=&status=` → review_items (grouped display is a UI concern;
  return group_key on each item).
- `POST /admin/review/{id}/approve|reject|merge` — approve APPLIES the proposal
  (listing_match → upsert listing; new_variety → create variety + listing;
  seller_candidate → create seller with eligibility 'candidate'; seller_correction →
  apply fields; removal → run R8 removal). Merge takes {into_id} for varieties:
  loser gets status 'merged' + merged_into_id, its aliases and listings move.
- `POST /admin/sellers/{id}/approve|reject|remove`.
- `GET /admin/stats/demand` → top clicked varieties, top sold-out clicks, top
  zero-result searches, top zero-seller variety views.
- `GET /admin/health` → invariant violations (published listing with unapproved
  seller, off-domain URL, or blocked domain), queue depth + oldest item, job stats.
- `POST /admin/rollup` → aggregate click_events/search_events into `daily_stats`
  (also exposed as `scripts/rollup.ts`).

## R12 — Search (canonical story 1)
- Two typed characters return matches (today the prefix fallback only fires when
  ALL terms are < 3 chars; the threshold becomes: any query of length ≥ 2 searches,
  using FTS where possible and prefix matching otherwise).
- Matches cover primary names AND aliases; a result matched via an alias is flagged
  (`matched_alias` + the alias text) and the UI shows "also sold as".
- Ranking: exact name → prefix → full-text; varieties with listings first on ties.
- Zero results: the page shows "Not in the catalog yet" + a report link; every
  search (page + API) writes a `search_events` row (query_normalized, result_count,
  client).
- API `/api/v1/search` returns mixed results {varieties, series, crops, sellers}
  with `type` and `limit` params, per canonical §3.

## R13 — API completeness + envelope (canonical §3)
- Add: `/api/v1/crops`, `/api/v1/crops/{crop}`, `/api/v1/varieties/{v}/listings`,
  `/api/v1/sellers/{s}/listings`, `/api/v1/series/{series}`, `/api/v1/coverage`
  (per crop: varieties, varieties with sellers, last updated), `/api/v1/recent`
  (recently restocked/newly listed from listing_events).
- Envelope gains `page: {next_cursor, has_more}` and `meta.catalog_seq` +
  `meta.generated_at`. Public listing objects carry `provenance` and never prices;
  variety/seller objects carry `rating` {state, average, review_count} and explicit
  `"unknown"`/null for unknown facts. Sort options: `name`, `recently_checked`,
  `listing_count` (± direction) — price sorts removed. List limit cap becomes 100.
- Rate limits: public reads 120/min/IP (exists), search 60/min/IP, reports 3/min/IP,
  ingest 600/min/key.
- New endpoints (ingest/admin/reports/sync) use `application/problem+json` errors
  with a stable `code`. Existing public reads keep the current error envelope.

## R14 — Pages and copy (canonical §1/§5)
- Home: search box, crop grid, recently restocked (from /recent data), coverage line.
- Crop page: intro (when the plant has one), filters (color_family, series,
  has_sellers) via query params, coverage counts + last-updated date.
- `/about/data`: how data is collected; who qualifies (small farm or seed shop the
  owner approves by hand; **a seller does not have to grow the seed it sells —
  bought-in seed is listed the same way**); source + date on every listing; opt-out
  and the 48-hour removal promise; disclosure that Hues owns and operates the site.
- `/about/bot`: bot name `HuesSeedFinderBot/1.0 (+https://seeds.hues.flowers/about/bot)`,
  robots.txt compliance, rate limits, opt-out route.
- Seller page gains a "Claim, correct or remove" link to /report.
- Variety page beacons a view to POST /api/track (extended: {type:"view",
  varietySlug} → variety_view_counts). Keep /api/track's existing click behaviour
  working for any legacy caller, but shop buttons now use /go (R7).
