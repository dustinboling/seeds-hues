# Seller-as-Shop — Locations Copy Rulings

**Seat:** Wren, Copywriting / Storytelling. **Commission:** the label strings for the Locations delta — Nadia's SPEC-LOCATIONS §6.1 fixes the slots and obligations and finalizes no string; this pass rules the set as one set.
**Date:** 2026-11-22 · **Status:** Ruled. These are the final words for the build; Mina composes them, Ada's floor pass follows, Quinn's delta gate closes.
**Governing rules applied:** US spelling throughout; plain, warm, factual directory voice, matching COPY.md's register; one pattern per job; omit needless words; the distinguishing word goes first, because scanners judge a label by its first word. Dustin's kind words — *physical*, *warehouse*, *mailing address* — are the taxonomy; this pass rules their exact strings, not their meanings.

**Notation:** `{name}` is the seller's display name, reproduced verbatim as stored. The possessive mark is always the typographic apostrophe (’, U+2019), formed by COPY.md §2's CS-05 rule: append **’s** unless the name's final character is "s", in which case append **’** only.

## 1. The section heading

**Ruled:** `{name}'s locations` — possessive per CS-05, sentence case, "locations" lowercase.

Renders as: `GeoSeed's locations` · `Plant Good Seed's locations` · `Three Brothers Blooms' locations` · `Johnny's Selected Seeds' locations`.

**Reasoning and obligations satisfied:**

- **It names the content as the seller's locations, and only theirs** (SPEC-LOCATIONS §6.1, slot 1). The possessive does the scoping work: this is the location set of this shop's record — not a directory list, not a state filing — which is exactly the §1.2/§2 boundary the area exists inside.
- **The plural never lies.** The area exists only when a seller has at least two qualifying locations (§5.4); a one-location seller renders no heading at all. "Locations" is therefore true every time the heading appears — the heading can never head a one-item list.
- **One pattern, learned once.** The page already names this shop `{name}'s shop` (base SPEC §3.1, COPY §2) and its search `Search {name}'s shop` (COPY §3). `{name}'s locations` is the same possessive frame with the content word swapped, so a visitor who has read the page's heading already knows how to read this one. The hard cases inherit CS-05's worked answers unchanged — a name already containing a possessive takes the rule mechanically (`Renee's Garden's locations`); the awkwardness is accepted there for the same reason: the seller's name stays intact and first.
- **Sentence case, "locations" lowercase,** matching "shop" in the shop heading. The name carries the capitals; the common noun does not compete with it.

## 2. The three kind labels — ruled as one set

| Kind (record value) | Ruled label (verbatim) |
|---|---|
| physical | `Physical address` |
| warehouse | `Warehouse address` |
| mailing address | `Mailing address` |

All three are sentence case, as displayed. Composition inside an entry — order, separator, dress — is Mina's; the strings are these.

**How the set works:**

- **One pattern: distinguishing word + "address".** Each label is a different first word over a shared noun. A scanner tells the three apart by the first word alone — *Physical / Warehouse / Mailing* share no letters, no sounds, and no meaning — which is what "mutually unmistakable at a glance" (§6.1, slot 2) requires in practice. The shared noun is what makes them a set: three kinds of one thing, the seller's addresses.
- **"Physical" takes the noun.** §6.1 leaves open whether "physical" stands alone; it does not. Standing alone it is an adjective with nothing to attach to — physical *what*? — and it would break the set's pattern, leaving one label a fragment beside two complete ones. `Physical address` is the visitor's own vocabulary for "the real place, as opposed to a box or a back office," and it is the only one of the three a visitor may drive to (§5.1.1) — the label carries that correctly: it names a place, because the kind is one.
- **`Warehouse address` names a function and makes no invitation.** The word "warehouse" in a visitor's vocabulary already means a working site, not a destination; the label adds no verb and no welcome, so it implies no visitability. It also claims nothing the record does not hold: this pass deliberately does **not** rule "Warehouse — not open to visitors" or any such rider, because no seller fact in the record says a given warehouse is closed to the public. The label states the kind; it does not invent a policy.
- **`Mailing address` can never read as a place to go.** "Mailing" names a channel, not a destination — it is the address you write *on* mail, in the phrase every visitor already uses ("mailing address" is the standard form-field phrase in US English). It contains no place word, no verb, and no invitation, and beside `Physical address` in the same list the contrast does the remaining work: one of these is where they are; this one is where their mail goes. A visitor who acts on it acts correctly — they mail something — which is the only action the kind supports (§5.1.1: a mailing address is only usable complete).
- **The labels are text, whole and unshortened,** satisfying §6.3's floor that kind is never carried by color, position, or icon alone. No abbreviation ("Mailing addr.", "Phys.") is ruled at any width; a label that needs shortening to fit is a layout problem, not a copy problem.

## 3. The primary marker

**Ruled:** `Primary` — one word, capital P, rendered as its own text on the primary's entry only, separate from that entry's kind label.

Renders beside any kind: `Physical address · Primary` · `Warehouse address · Primary` · `Mailing address · Primary` (separator and placement are Mina's; the two strings are never merged into one).

**Reasoning and obligations satisfied:**

- **It reads as a status, not a kind** (§6.1, slot 3). "Primary" is a rank adjective — it says where this entry stands among the seller's locations, not what sort of place it is. It therefore cannot be mistaken for a fourth kind label in a list of three, which is the failure the slot's obligation exists to prevent.
- **It makes sense beside every kind label, unchanged.** The primary may be any kind (§5.3) — including, for a seller whose directory presence is a mail drop, a mailing address. `Mailing address · Primary` is coherent precisely because the two strings answer two different questions (what kind is it / is it the main one). That orthogonality is why the marker is **never folded into the kind string**: a merged form like "Primary mailing address" would make "primary" read as part of the kind and would need a different merged form per kind. Two strings, two facts, per §5.3.
- **The rejected forms, for the record:** "Primary location" and "Main location" both end in a place noun and so read as kinds or as a place name beside the kind labels; "Home location" implies a residence, which a farm, warehouse, or PO Box is not. "Primary" alone is also the directory's own word for this fact (the one-primary rule, §1.1), so the marker teaches no new term.
- **Text, never position or color alone** (§6.3 floor, §5.3): the primary is also listed first (§5.2), but position only reinforces the marker — the word carries it, including non-visually.

## 4. Intro line — none

**Ruled: no intro line.** The conditional slot (§6.1, slot 4; §4.4) is not triggered: the heading names whose locations these are and what the set is, the kind labels say what each entry is, and the marker says which one is primary. Nothing a visitor needs is left unsaid. An intro could only repeat the heading ("All of {name}'s locations are listed below"), restate a label ("Mailing addresses are for mail only" — already what `Mailing address` says), or narrate the directory's one-primary rule, which is the team's filing discipline, not a fact a shopper needs at this section. A paragraph that repeats its own heading on every multi-location shop also trains visitors to skip it. Silence is the ruling, per §4.4's default.
