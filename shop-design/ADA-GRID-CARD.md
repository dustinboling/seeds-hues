## G-A1 — Floor (a): shop-context heading structure: **CONFIRMED**

- **Shop context:** the variety name is an `<h3>` under the catalog section's `<h2>` (`"{name}'s shop"`), exactly as the ledger's card heading was — page outline: `<h1>` (seller) → `<h2>` (About / Locations / shop, as present) → one `<h3>` per shop card, the card's variety name, containing the name's link to `/variety/{slug}`. No level is skipped (1.3.1, 2.4.6); no card carries a second heading; the Latin line, crop line, stock line, and packet list are **not** headings and must not be marked up or styled into heading semantics.
- **Browse context:** the shipped pattern stands — **no per-card heading**. The browse card's name is text inside the whole-card link, structured by the page's own headings (the crop/series/browse `<h1>`/`<h2>` above the grid). Adding `<h3>`s to browse cards is not an improvement this seat will trade for: a 24-card browse grid would inject 24 headings into the outline, drowning the page structure screen-reader users navigate by, to name links that floor (b)'s accessible name already names. The asymmetry between contexts is therefore ruled **correct and intentional**, not an inconsistency: the shop card is not a whole-card link, so its name needs a heading to be findable as a heading; the browse card is one link, so its name needs an accessible name, not a heading.
- **Binding obligations:** exactly one `<h3>` per shop card, containing exactly the variety name (no crop, Latin, or stock text folded into the heading — a heading that absorbs its card's facts makes heading-navigation useless); skeletons render no headings at all; in-place filter/search/sort updates never change the heading structure, only the set of `<h3>`s present.

## G-A2 — Floor (b): the browse card's `aria-label` versus the Latin line: **CONFIRMED — Nadia's recommendation stands**

**Ruling: the shipped `aria-label` stands, unchanged in form — `"{varietyName} — {crop}"`, where `{crop}` is the short common name (Wren, COPY-GRID-CARD §1, the same short form the visible crop line now takes in both contexts, so the heard name and the seen subline agree). The Latin line is visible text inside the link. It is not added to the accessible name.**

Reasoning, stated fully because this is the floor a builder is most likely to "improve" wrongly:

1. **A concise name beats a complete name for a link.** The browse grid is a scanning surface: a screen-reader user moving link to link hears one name per card, up to 24 per page. `"{varietyName} — {crop}"` identifies the destination (2.4.4 — link purpose, met: the name *is* the variety page's subject). Appending the Latin string would make every name longer, and the worst names unusable — the multi-species strings run to 49 characters and three species ("Asclepias tuberosa / A. incarnata / A. physocarpa"); a links list narrating full botanical strings per card taxes exactly the navigation the concise name exists to speed. Latin is supplementary identification (floor (d)); the variety page itself carries it in its eyebrow and facts table, one tap away, where it belongs to the page's content rather than to a grid link's name.
2. **What the `aria-label` does to the Latin line, said honestly.** An `aria-label` on the link overrides its contents for the accessible name: the Latin line (and the name, crop, and seller-count text) inside the link are not separately announced as the link's name, and in browse context a screen-reader user will not hear the Latin string from the card. That consequence is **accepted, and it is not an information loss under the criteria**: the Latin line carries no fact the task needs (it is never a sole carrier — G-A4), its absence from the name is uniform, and the same string is perceivable on the destination page. The alternative — dropping the `aria-label` so the name computes from content — was considered and rejected: the computed name would concatenate art alt, Latin, name, crop, and seller count into one undifferentiated string, worse on every count than the ruled name, and it would change a shipped, working pattern to solve a non-failure.
3. **Prescriptions that keep the ruling true:** (i) the Latin line inside the browse link is plain visible text — no `aria-label` of its own, no `role`, no separate focus or announcement; do **not** mark it `aria-hidden` (it is not decoration; hiding it from the tree while its siblings are overridden anyway adds a second, inconsistent suppression, and in any future no-`aria-label` rendering it must be present); (ii) the `aria-label`'s crop segment must be built from the same `shortCommonName` value as the visible crop line — a label that named the full "Cornflower / Bachelor's Buttons" while the card shows "Cornflower" would break label-in-name discipline (2.5.3) for voice-control users matching what they see; (iii) in **shop context there is no card-level `aria-label`** — the shop card is not a whole-card link (SPEC-GRID-CARD §3.4), its name link's accessible name is the variety name text itself, and its Latin line is ordinary readable text in the card, available to assistive technology in reading order. The two contexts differ here for the same structural reason as in G-A1, and both are correct.

## G-A3 — Floor (c): focus order, target size, and focus visibility in the shop card: **CONFIRMED, with the heading-link target prescribed exactly**

- **Focus order (2.4.3): heading link → "Report a problem" → "Visit shop →" pill** — in that order, which must be the DOM order; no positive `tabindex` anywhere in the card or grid; no element reorders the sequence visually against the DOM (a footer laid out Report-left / pill-right in the same row is the DOM order seen, 1.3.2 satisfied). Across the grid, focus moves card by card in reading order — a keyboard user traverses the shop's products in the same sequence a sighted user scans them. The browse card contributes exactly one tab stop per card (the whole-card link); no inner element of a browse card is focusable.
- **Target size (2.5.8 AA floor 24×24; the house standard this seat designs to is 44px): all three shop-card targets measure at least 44×44 CSS px.** Report and the pill already meet this in the ledger's dress and carry it over unchanged. **The heading link is the one target whose natural text box can fall short** — a one-line variety name at 18px/`leading-snug` is a ~25px-tall line box — so this seat prescribes exactly: **the name link is `display: block` (or inline-block stretched by its `<h3>`) with `min-height: 44px`, spanning the card's text width, its text vertically within that box; the 44px is measured on the link's rendered border box, not on its line box.** A build whose heading link measures under 44px tall fails this ruling even if Report and the pill pass. (The browse whole-card link exceeds every minimum by being the card; no measurement is owed beyond its full-card extent.)
- **Focus visible and never obscured (2.4.7, 2.4.11; appearance per 2.4.13 as this seat's standing design target):** every focusable element in both grid contexts takes the global ring — 3px + 2px offset, focus `#7A3E10` at 7.3932:1 on paper / 8.1745:1 on surface, more than double the 3:1 non-text floor (1.4.11). The grid-specific risks are clipping and crowding, and both are prescribed against: **no card, frame, or grid cell may clip the ring** (no `overflow: hidden` on the card or its text zone that intersects the ring's 5px extent; the grid's `gap-2` plus card padding must leave the ring fully drawable around a focused card link and around each shop-card control — Quinn measures the rendered ring, not the CSS); **no sticky or floating element exists in the grid region** that could cover a focused card, and the page's sticky furniture, if any, must leave the focused card fully visible at phone width and at 400% zoom — `scroll-margin` on cards/controls is the accepted mechanism if the build needs it. In forced-colors mode the ring must be outline-carried, never shadow-carried (the standing condition from `ADA-RULINGS.md` Ruling 10, applied here: the sold-out card's softened shadow is dress, never a state or focus carrier).

## G-A4 — Floor (d): the Latin line and the stock dot are never sole carriers: **CONFIRMED**

- **Latin line:** supplementary text, full stop. It identifies nothing alone, gates nothing, and encodes no state: variety identity is always carried by the variety name (present on every card in both contexts) and the crop by the crop line; a card with no Latin line (G-A5) loses no information a shopper needs to choose or navigate. Its distinction from the crop line is carried by italic form, by position, and by the name standing between them (Thea T-1/T-7) — never by colour alone; Thea's `text-muted` is the same token the crop and availability lines use, so no colour distinction between Latin and crop is even attempted (1.4.1 satisfied by construction). The one thing the build must not do is *promote* the Latin line into a carrier — no stock, availability, or filing meaning may ever be read from its presence or absence.
- **Stock dot:** the dot is `aria-hidden` decoration beside its word, as today. Stock is carried by the **word** — `In stock` / `Sold out` / `Preorder` / `Shop closed` / `Unknown` (Wren, COPY-GRID-CARD §3) — plus the checked date (`Checked {date}` / `Not yet checked`), in text, in reading order. Colour and the dot may agree with the word; they may never replace it, and no state (including the sold-out dress: stepped-down ground, softened shadow, outline-only pill — SPEC-GRID-CARD §3.3) is a sole carrier: a sold-out card read in forced colors, in grayscale, or aloud still says "Sold out" in words and its pill still works. That redundancy is the ledger's shipped discipline, transferred whole, and this ruling holds the grid card to it without dilution.
- **Artwork channels, for completeness:** Elena's tier order changes what the frame shows, not what anything means. Tier 1 alt `"{varietyName} — illustration"` and tier 2 alt `"{crop common name} — illustration"` name their actual subject (the crop plate is never alt-texted as the variety — ART-GRID-CARD §1.4); tiers 3–4 (the pod device in crop and generic forms, on `paper-deep`) are decorative — `alt=""` and `aria-hidden` — and the `paper-deep` ground itself carries no text and creates no contrast pair, so its change from `bg-paper` raises no floor question. A placeholder frame must never be the only signal that a variety lacks its own plate; under this design it signals nothing at all, which is correct — plate provenance is not shopper-facing information.

## G-A5 — Floor (e), part 1: Latin absence — no announcement, no layout shift: **CONFIRMED (mechanism verified)**

SPEC-GRID-CARD §6.3's absence rule — when `plant.latinName` is `null` (269 of 812 varieties at launch), the Latin line does not render: no placeholder text, no "Latin name unknown", no empty slot, no derived or guessed name — is the correct behaviour under this floor, and the fixed zone is a sound mechanism for it. The reasoning, verified link by link:

- **No announcement:** an absent element announces nothing. There is no live region on the card, no `role="status"`, and no state change at render — the card is server-rendered with or without one text line, and assistive technology reads what is there. The ruling's condition is that absence stay *elemental*: the build must render **no node at all** for a null Latin name — no empty `<span>`, no visually-hidden text, no `aria-hidden` placeholder holding the space. An empty reserved element would be a detectable "something is missing here" in the tree and a defect under this ruling; a missing element is silence, which is what absence should sound like. (DOM-absent iff `plant.latinName` is `null` is exactly Quinn's SH-G6 diff — adopted as this floor's check.)
- **No layout shift:** the text zone's height is fixed by the zone, not by the card's content, and the remaining lines centre in it (Thea T-7) — so a Latin-less card is pixel-equal in height to its Latin-carrying neighbours in the same row, art frames align, and nothing moves when grids render in any state (filtered, searched, paginated). The same holds in shop context by the other mechanism: the fact block flows and the footer is pinned (`margin-top: auto`), so a missing Latin line moves the fact block up within the card and moves nothing outside it. One honesty note, carried from Thea §7: centring means the Latin line's *top edge* is not at a fixed height across a row (it rides on the name's line count below it). That is a visual-rhythm observation, not a layout shift in the criterion sense — card boxes, frames, and rows are stable; no content relocates after render; nothing here engages 1.4.12 or the shift concern this floor names. Recorded so the gate does not mistake it for a failure of this ruling.
- **No shift on state change either:** a Latin line never appears or disappears because of a filter, search, or sort (SPEC-GRID-CARD §4.4) — presence is a function of the variety's data only, so in-place updates cannot introduce a card whose zone geometry differs from its pre-update self.

## G-A6 — Floor (e), part 2 — the Thea flag: the fixed zone under WCAG 1.4.12 text-spacing overrides: **FAILS AS A LITERAL FIXED HEIGHT — prescribed: the zone is a floor, not a ceiling**

**The flag (Thea, TYPE-GRID-CARD §6, addressed to Ada and Mina jointly).** Thea rules the Latin allocation at up to 3 lines / 60px and the grown browse zone at 9.75rem (156px), holding the worst-case stack at default leading: Latin 3 × 20px + name 2 × 24.75px + crop 20px + availability 20px + gaps 6px = 155.5px. She then flags: WCAG 1.4.12 lets a reader impose line-height at 1.5× the font size (with letter spacing 0.12em, word spacing 0.16em, paragraph spacing 2×), under which the same worst stack computes to **~180px** — more than any zone sized at the default leading. A fixed-height zone with centred content clips under that override.

**This seat's verification of the arithmetic.** Recomputed at the override values: Latin 3 lines × (1.5 × 14px = 21px) = 63px; name 2 lines × (1.5 × 18px = 27px) = 54px; crop 21px; availability 21px; inter-line gaps grow with paragraph spacing — the stack lands at **~165–180px depending on how the override's paragraph spacing maps onto the stack's gaps**, i.e. 9–24px beyond the 156px zone on the worst card (3-line Latin + 2-line name), before letter/word spacing is counted at all. Letter spacing 0.12em additionally widens every line, so at narrow measures strings that wrapped to 3 lines at default spacing can wrap to **4** under the override — each extra Latin line adds a further 21px. Thea's ~180px is, if anything, conservative. **A zone built as `height: 9.75rem` with centred, non-growing content therefore fails 1.4.12 (Text Spacing — no loss of content or functionality when the overrides are set) on exactly the cards the 3-line allocation exists to protect: the full Latin string would clip — content loss of the very species names §6.2 forbids rewriting — and centred clipping takes lines from both ends symmetrically, so the name can clip too.** Flagged plainly: **as a literal fixed height, the mechanism in floor (e)'s wording fails. As a minimum, it passes. The prescription below is the difference, and it is binding.**

> **Prescription — floor-not-ceiling (binding on the build; for Mina to carry into the zone's values).**
>
> 1. **The browse text zone is sized with `min-height: 9.75rem` (156px), never `height`.** At default spacing it behaves exactly as Thea and Nadia ruled — fixed, uniform, centred, rows aligned, absence invisible (G-A5 unchanged: uniformity at default settings is preserved because every card's zone is *at least* 156px and the worst default stack is 155.5px).
> 2. **Growth, never clipping, never internal scroll.** The zone carries **no `overflow: hidden`** (and no `overflow` value that creates a scroll container) and no clipping mask. When user spacing overrides — or 200% resize, G-A7 — make the content taller than 156px, **the zone grows to fit its content**, the card grows with it, and the row grows to its tallest card (the grid's existing `h-full` stretch keeps the row uniform). Text is never cut off at the zone's edge, lines never overlap, and the card never scrolls internally: an internally scrolling card would fail 1.4.12's no-loss test in practice (content reachable only inside a nested scroller, focus at risk of scrolling out of view under 2.4.11) and is prohibited, as is any ellipsis/clamp introduced to defend the height — Thea T-5 already forbids clamping the Latin string, and this ruling extends the same prohibition to every line in the zone under overrides.
> 3. **The 3-line Latin allocation is a default-spacing allocation, not a cap.** Under letter/word-spacing overrides the Latin line may wrap beyond 3 lines; the zone absorbs however many lines result, by rule 2. No build logic may count lines.
> 4. **Shop context needs no parallel fix and must not acquire the defect:** the shop card's text block is in flow with the footer pinned by `margin-top: auto` (SPEC-GRID-CARD §3.3, Thea §6) — it already grows. The build must keep every shop-card text container free of fixed heights for the same reason; the pinned footer absorbs variance at default spacing and the card simply grows under overrides.
> 5. **Centring under growth:** the stack stays `justify-center` within the *grown* zone — when the zone is exactly 156px the behaviour is Thea's T-7 verbatim; when it has grown, the content fills it by construction, so no new alignment case arises.

**What the build gate should check (Quinn — add as SH-G13a; this is the check this ruling will be judged by):**

- Apply the WCAG 1.4.12 override set verbatim (line-height 1.5×, letter-spacing 0.12em, word-spacing 0.16em, paragraph spacing 2× font size, via the standard bookmarklet/stylesheet method) at 390px and at 320px, on the worst-case fixture — a card with the 3-line Asclepias Latin string **and** a 2-line variety name — plus a Latin-less card in the same row.
- **Pass requires all of:** the full Latin string visible, every species, no ellipsis; the variety name, crop line, and availability/stock line fully visible, no clipped ascenders/descenders, no overlapping lines; the zone's rendered height ≥ its content's height (no element's `scrollHeight` exceeds its `clientHeight` inside the zone); the card exposes no internal scrollbar; the page shows no horizontal scrollbar; the Latin-less neighbour's card matches the grown row height with its stack unclipped; keyboard focus on the browse card link and on each shop-card control shows its full ring inside the grown card.
- A clipped line, an internal scrollbar, or a horizontal scrollbar under the overrides is a **FAIL against 1.4.12**, attributable to this ruling — not a cosmetic note.

## G-A7 — Floor (f): grid reflow at 320px and 200% text, no horizontal scroll: **CONFIRMED, as conditioned by G-A6**

- **320px reflow (1.4.10):** the grid is 2 columns at phone widths (the standard variant's shipped geometry), one-dimensional in flow, with no fixed minimum card width that could exceed the container: at 320px the card text measure is 108px (Thea's derivation), and the longest single word in any Latin string ("physocarpa", 63.7px at 14px) fits that measure with room — natural wrap never needs to break a word, and no string, name, or label in the card's ruled set can force the grid wider than the viewport. The art frame is proportional (full card width, 1:2), so it narrows with the column and can never overflow it. Confirmed: no horizontal scroll, no two-dimensional scrolling, nothing essential pushed off the magnified viewport — subject, as every design-stage reflow ruling is, to Quinn's rendered proof at 320px (SH-G13).
- **200% text (1.4.4):** text scales in relative units throughout the card system; the Latin line wraps to more lines rather than widening (its measure is the card's, and wrap is natural per Thea T-5); the text zone's behaviour under the resulting taller stack is G-A6's growth rule — **this is where floor (f) depends on the G-A6 prescription: with a literal fixed height, 200% text on a worst-case card clips for the same reason the spacing overrides clip, and floor (f) would fail with it.** With `min-height` and growth, cards lengthen, rows lengthen, and the page scrolls vertically only — which is the criterion's expected outcome, not a failure. Packet lists and notes in shop context wrap and grow the same way; the pinned footer moves down, never over text.
- **Forced colors, recorded with this floor:** card boundaries and focus are border/outline-carried (G-A3); the artwork is a true colour specimen and may keep its colours (the standing specimen exemption); the sold-out ground step may vanish under forced colors without loss, because the stock word carries the state (G-A4).

## §9 — Gate inputs for Quinn (SH-G13, extended; consume verbatim)

SH-G13 in SPEC-GRID-CARD §9 stands; this pass rules its content as follows and adds one check:

- **SH-G13 (as ruled here):** at 320px and at 200% text, both grids reflow without horizontal scroll or clipped focus (G-A7, G-A3); a keyboard walk of a shop card visits heading link, Report, pill in that order, each target's rendered box ≥44px in both dimensions (heading link measured on its border box, G-A3), each ring fully visible and unclipped; a screen-reader pass over a browse card announces exactly `"{varietyName} — {crop}"` (short crop form) as the link name, and over a shop card announces the `<h3>` name, the stock word (never the dot), and the pill's purpose ("Shop at {name} (opens in a new tab)" per COPY-GRID-CARD §5); stock state is never carried by the dot alone (G-A4); a Latin-less card's DOM contains no Latin node, no empty placeholder element, and its height equals its row neighbours' (G-A5).
- **SH-G13a (new, from G-A6):** the 1.4.12 override drive and pass conditions stated in G-A6, on the Asclepias + 2-line-name worst-case fixture at 390px and 320px. A clipped line, internal scrollbar, or horizontal scrollbar under the overrides FAILs the gate against 1.4.12.
