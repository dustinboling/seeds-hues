**PASS WITH NOTES — conditional. The design may be briefed for build once (1) Dustin rules the three named decisions in §6, and (2) the six pre-build amendments in §5 are applied to SPEC.md and the CSN series.**

This is not a clean PASS, and the conditions are not decoration. SPEC.md as written still states, in normative sections, a behavior model that three of the other four documents have superseded (§3, defects Q-D1…Q-D3). A build briefed today straight from SPEC §§3.1/4.5/7.1 would build the wrong eligibility rule, and CSN-10 as written would fail that wrong build's correct twin and pass the wrong one. Every inconsistency found, however, already has its reconciled form written, in full, in at least one document in this set and ratified by the seat that owns it — Wren's S4 with its marked one-line swap, Mina's §8/§8.5 costing both models, Priya's §4.2 enforcement, Ada's rulings designed for either outcome. If Dustin rules against the reconciled model on Decision 1, the design still passes — Nadia's model is fully designed (§8.5 of UI-DESIGN; S4's one-line swap) — but the amendment set in §5 flips direction, as noted there.

**Four axes, kept separate (playbook W2):**
- **Severity:** 0 Blocker, 0 Critical, 3 Major, 6 Minor defects (§3). No defect is in shipped code; all are document defects caught at the cheapest point they can be caught.
- **Evidence:** directly read — every claim below cites the section it was read in. Contrast and geometry figures are the documents' own computed values, independently recomputed by Ada (§5 of her rulings, all 20 pairs); Quinn did not recompute them a third time and does not claim to.
- **Coverage:** complete for the design set as commissioned — see the coverage ledger, §7. Rendered behavior, screen-reader behavior in real AT (NVDA/JAWS/VoiceOver), and Priya's build-spike items are named exclusions, owed at the build gate.
- **Evaluator structure:** single evaluator (Quinn). No cold second rater was commissioned for this design gate; per the evaluator-effect evidence in this seat's playbook, a single pass finds roughly a third to two-fifths of the problems a group would. The build gate on the rendered feature — interactive work — is where a second rating (Athene) should be commissioned. Recorded here so this verdict is not read as evaluator-neutral.

## 3. Defects found (one per item; severity on the playbook scale)

### Major

- **Q-D1 — Two clocks, and one state vocabulary for two different state machines (found by this gate; raised by no document).** SPEC §0.1/§3.1/§4.3 define freshness and eligibility solely from `lastCheckedAt` (last *observation*). ENGINEERING §4.1–4.2 explicitly rejects that clock for the window — `attempted_at` is the 24h clock, precisely so an ingest observation cannot reset the public's force-check budget — and its response contract (§1.2) then reuses the words `fresh`/`stale` with different meanings (API `fresh` = attempt inside window **and** outcome `ok`; SPEC state (c) fresh = observation <24h old, however produced). Under the API definition, a listing crawl-observed one hour ago with no CSN attempt is not `fresh`; under SPEC it renders fresh with no control. No document contains a UI-state ↔ API-state mapping. **Expected:** one eligibility rule and one mapping. **Required (pre-build, §5):** eligibility is the conjunction — observation ≥24h old or absent **and** attempt ≥24h old or absent **and** checkable **and** not block-listed **and** not in flight — and the build brief carries a mapping table from Priya's `state`/`outcome` pairs to Nadia's five UI states. Severity Major: a builder implementing either document faithfully, alone, produces a different feature.
- **Q-D2 — SPEC §3.1's clock-only eligibility renders the control where a check can never fire (PB-W2/PB-W3).** §3.1 offers the control "if and only if" the clock says so. Priya's taxonomy (§§1.1 steps 4–6, 2.4) refuses `manual_only`/`opted_out` sellers, null product URLs, and block-listed domains without a fetch. On those listings a click promises a check engineering will not run, and on blocked domains S4-A's "We tried to check" would be false — the attempt that discovers a block is the only honest S4-A. Wren's copy ruling (no control, no notice) is correct and is adopted. **Required (pre-build, §5):** SPEC §3.1 amended to eligibility = clock **and** checkability (policy, product page present, domain not blocked), evaluated server-side per ENG §1.1's order.
- **Q-D3 — SPEC §§4.5/7.1 and D-CSN-4 still state the superseded couldn't-check model as normative.** Immediate control return (§4.5, §7.1's "eligibility is unchanged"), participant-only notice (§4.5 persistence, D-CSN-4) — contradicted by ENG §4.2, COPY S4/PB-W1, UI §8/DR-1, and Ada §§3.3/7.5, all written to the reconciled attempt-keyed model. This is the document-set form of the CSN-10 defect (§2). **Required (pre-build, §5):** §§4.5/7.1 and D-CSN-4 amended to whichever model Dustin confirms under Decision 1; until then SPEC must not be briefed from directly. Severity Major, not Critical: the reconciled text exists in full in three documents, so the fix is an amendment pass, not new design.

### Minor

- **Q-D4 — CSN-7 asserts announcement text but not timing or non-persistence** (PB-W4; Ada §2.5). Fixed by the CSN-7 re-point (§2).
- **Q-D5 — CSN-15 and CSN-2 each miss one case a ruling in this set requires:** state-(e) focus landing under the reconciled model (Ada §3.3) and the 320px + 1.4.12-override grid case (Ada §7.4). Fixed by the CSN-15 and CSN-2 re-points (§2).
- **Q-D6 — The attempt bound is two numbers and CSN-12 names neither** (found by this gate). ENG §1.4: 25s executor deadline, 30s polling ceiling; SPEC §7.2 recommends a 30s bound; UI §6 repeats both side by side. The numbers are compatible (deadline produces the outcome; ceiling bounds the wait) but no document says so in one place. Fixed by the CSN-12 re-point (§2); the build brief must state the pair as one rule.
- **Q-D7 — Blocked clicks stamping `attempted_at` can delay the first post-expiry probe** (found by this gate). ENG §5.2 stamps `attempted_at` on blocked clicks; §5.5/§1.1 make the first check after `blocked_until` passes a normal check — but a click one hour before expiry leaves the attempt window closed for up to 24h after the block lifts, so the domain's one-shot re-probe can be silently deferred by a day. Minor (self-healing, no false public statement), but the build brief must state the intended interaction — recommended: a blocked outcome's stamp does not extend past `blocked_until`.
- **Q-D8 — S4's assembled length exceeds Mina's §15 length recommendation; accepted knowingly.** Mina recommends one sentence, ≈90 characters, so the grid-card notice wraps to ≈4 lines. Wren's final S4 is three sentences, ≈150 characters assembled (e.g. S4-A with prior observation) — on the grid card's 143px measure that is roughly 7–8 lines, absorbed by the pinned footer. Mina's own OQ-M2 pre-rules this outcome: length is a recommendation to copy, never a license to cut a fact, and the design accepts the longer wrap. **Disposition: accepted deviation, cost named, no amendment.** Recorded so the taller couldn't-check grid card is a decision on the record, not a surprise at the build gate.
- **Q-D9 — SPEC §0.2's "a failure is never cached as a result" misstates the mechanism** (PB-W6). Engineering *does* cache the attempt (the window keys on it); it never caches an *observation*. Wren's suggested wording — "a failure is never cached as an observation and never moves `lastCheckedAt`" — is adopted as a §5 spec-clarity amendment. No public copy turns on it.
