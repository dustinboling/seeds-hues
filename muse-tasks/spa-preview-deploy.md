## Deliverables

1. **Worker entry** (suggested `app/server/worker.ts`): a web-standard `fetch` handler composing the same routes as `server/serve.ts`, route for route — Workers Static Assets for `dist/client` files and machine files; `POST /internal/revalidate`; `/og/[kind]/[slug]`; the SSR floor POSTs (`/report`, `/add-your-farm`); `GET /go/[id]`; the admin POST actions and the admin GET gate; the `/api/v1/*` and `/api/internal/admin/*` relays to the API origin; `/healthz`; `/api/track`; `/api/client-errors`; the in-memory edge mock for detail 200s (per-isolate Map is fine); everything else through Vike `renderPage` with ONE shared catalog client + data cache per isolate. Node-only mechanics translate: static reads → the ASSETS binding; gzip → the edge (drop the manual gzip); socket IP → `cf-connecting-ip`. Build it with **`@cloudflare/vite-plugin`** per the architecture brief, as an **additive** build path: its own Vite config file + an npm script (`build:worker`). The existing `npm run build`, `npm run build:server`, `npm run serve`, and the whole existing verify suite keep their current behavior exactly — if the Cloudflare plugin cannot be integrated without changing the existing build's output, keep it isolated in the separate config rather than bending the existing one.
2. **The variety-status mount, from D1** (the one Phase B mount the preview carries): `GET /api/internal/variety-status/[slug]` in the Worker, reading the `DB` binding with SELECT only, answering exactly the contract the app + stub pin (always 200 `{status, merged_into}`; a `status='merged'` row resolves `merged_into` the way the stub does; soft-deleted or absent slugs are the unknown class). No other D1 use anywhere in the entry.
3. **Preview config** `app/wrangler.preview.jsonc`: Worker name `seeds-hues-preview`; `workers_dev: true`; **no routes, no custom domains**; the Static Assets binding over the worker build's client output; D1 binding `DB` → the production catalog database (`seeds-hues`, id `dcc6098e-e48c-4906-ac79-72cc77e04042` — read by the variety-status mount only); vars `SEEDS_API_BASE=https://seeds.hues.flowers/api/v1`, `SEEDS_TURNSTILE_SITE_KEY` (the public site key, copied from `v2/wrangler.jsonc` vars), `SEEDS_PREVIEW=1`. **No secrets in the config** and `SEEDS_REVALIDATE_SECRET` deliberately unset (the revalidate mount answers not-configured in preview). Add a `deploy:preview` npm script (`wrangler deploy -c wrangler.preview.jsonc`) and `wrangler` as a devDependency; the script is for the coordinator — do not run it.
4. **Preview SEO shield:** when `SEEDS_PREVIEW` is set, **every** response the Worker serves carries `X-Robots-Tag: noindex, nofollow` (forced over the route-class header set) and `GET /robots.txt` serves a disallow-all body (`User-agent: *` / `Disallow: /`). When the flag is unset, behavior is exactly production-shaped — this entry is the cutover's foundation, so the shield lives behind the flag only, never as an unconditional change to shared header paths.
