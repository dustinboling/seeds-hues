## 0. What already exists, and what the gap actually is

This commission does **not** start from zero, and the build must not create a parallel system. Measured from the code and the live site:

- A component already exists: **`StateShape`** (`v2/components/seller/StateShape.tsx`), backed by the generated data table **`STATE_SHAPES`** (`v2/lib/data/state-paths.ts`, generated by `v2/scripts/gen-state-paths.py` from `state-shapes/state-paths.json` — never hand-edited). It is already placed in three surfaces (filter chips, seller cards, seller page) with exactly the semantics this spec requires: square box, `preserveAspectRatio="xMidYMid meet"`, `aria-hidden`, non-scaling stroke, render-nothing fallback.
- **The gap is coverage, not placement.** `STATE_SHAPES` covers **16 states** (CA, CO, CT, GA, IA, ME, MN, MT, NV, NY, OR, UT, VA, VT, WA, WI). Sellers now span **31 states**. The 15 missing — **FL, ID, IN, KS, MO, MS, NC, ND, NJ, NM, OH, PA, SC, TX, WY** — silently render nothing today. Verified live 2026-11-22:
  - The seller index filter renders 31 state chips (`data-state` attributes, matching the commission's 31-state list exactly); only 16 carry a `data-state-shape` outline.
  - GeoSeed's seller page (`/seller/geoseed`, South Carolina): the Location state link renders with its icon slot literally `null` beside the text "South Carolina."
  - The Oregon state page renders 9 `data-state-shape="OR"` outlines — all from seller cards; **the page's own heading has none**.
- **One commissioned surface has no icon at all:** the state page H1 (§2.1). That is the only genuinely new placement in the original commission.
- **A fifth placement was ruled in later the same day:** the variety-page listing card (A5). Dustin ruled state outlines onto those cards on 2026-11-22 (16:41 PT); Nadia supplied the structure change — the subline renders the seller's state as structured data (`SPEC-LISTING-CARD.md`) — and the placement is folded into §1, §2, and §7 (D7) of this revision. It was formerly ruled no-icon as N5; see §8.3 for the supersession.
- Out of scope and untouched: `StateShape`'s `art` variant (flower artwork clipped to the outline) is unused in production — it appears only in tests — and the state-flower **StatePlate** and state hero scenes are artwork surfaces governed by the state-plates placement spec (2026-11-19), not by this one.

**So the build is four things:** (1) complete the set to all 31 seller states — all from Elena's geometry, one vintage (§7 D6) — through the existing component contract and the generator bridge (§5), (2) add the new placements — the state page H1 (A1, §2) and the variety-page listing card segment (A5, §2), (3) tokenize the sizes that are currently raw numbers in code (§6), (4) repaint every placement to `currentColor` with no fill (§7 D5). Everything else in this spec is the register that proves nothing else moved.

## 2. Placement spec per surface

All sizes below are the component's **square box** (§3), not the glyph's drawn size. All gaps are existing spacing-scale steps — no new gap values are introduced. Alignment in every host is **optical center** (`align-items: center` in the existing flex/inline-flex hosts): an outline glyph has no baseline, so baseline alignment is never used; the box centers on the name's line box.

**Color — RULED BY IRIS (applies to every row).** Elena's set is specified stroke = `currentColor` with no fill. Iris ruled for the pairing proposed here (`IRIS-COLOR.md`): **the icon inherits the color of the name text it accompanies**, per surface — ink on resting chips, leaf on the active chip, muted on the seller card, link color on the seller page link, leaf in the state H1 (the H1 is `text-leaf`). This makes every state of every host (hover, active, focus) color the icon automatically, and in forced-colors mode the stroke follows the text color instead of disappearing. It supersedes the current production paint (fixed `stroke-leaf` + `fill-leaf/8`), which does not follow host state — on today's active chip the outline happens to match, on a resting chip it does not. The ruling is registered as a definite rendered difference in §7 (D5). Iris extended the same ruling to A5 unchanged (`IRIS-COLOR-A5.md`): `currentColor` → `--color-muted`, no fill. Stroke width for all placements: **1.25 px, non-scaling** (`vector-effect="non-scaling-stroke"` — the existing behavior below the 80 px art threshold), tokenized in §6.

## 3. Aspect handling — the fixed-box rule

States are the worst aspect spread of any icon set: in the current geometry (viewBox width normalized to 100) heights run from **44** (Montana — very wide, very short) to **163** (Vermont — very tall), with California at 116 and Colorado near-square at 74. Elena's set will differ in constants but not in kind: Texas wide, Idaho and California tall, Colorado square. The rules below are written against the *spread*, not against any one set's numbers.

1. **One fixed square box per surface** (§2). The box never varies by state. The glyph is fit **inside** it with `preserveAspectRatio="xMidYMid meet"` — the long axis touches the box, the short axis letterboxes, the glyph is centered on both axes. This is the existing `StateShape` behavior; the build keeps it exactly.
2. **Never size by native aspect.** No variable-width or variable-height boxes, no per-state size overrides. A row of chips, a grid of cards, and a list of links must present the same geometry for Texas as for Vermont — the name's starting position may differ *between* surfaces, never *within* one surface because of a state's shape.
3. **Never stretch.** `preserveAspectRatio` is never `none`; no `object-fit`-style distortion, no cropping of the outline. A distorted state is a wrong state.
4. **Stroke weight is independent of glyph scale.** Because `meet` scales a tall state down and a wide state across, a scaling stroke would render Vermont's outline thinner than Montana's. The stroke is therefore **non-scaling** (`vector-effect="non-scaling-stroke"`) at the token width (1.25 px) on every state, at every size in §2 — the existing behavior, now stated as a rule the new set must land inside. Under Elena's set the viewBox is uniform (24 units) for every state, so a scaling stroke would in fact be uniform *across states*; the rule stands on its surviving grounds — one stroke weight at every size in §2 (20–32 px), and the existing component contract — and §5.1 records the reconciliation with Elena's drawing-grid weight.
5. **Unequal ink is accepted, deliberately.** Fitted into the same box, a wide state (Montana, Texas) carries less visual weight than a tall one (Vermont, Idaho). That is the price of recognizability and row alignment, and it is the field-standard answer (keyline systems fit glyphs to a shared box rather than equalizing ink). **Do not compensate** by enlarging wide states past the box — that trades a quiet optical difference for broken alignment on every row.
6. **Overflow safety.** The box is `shrink-0` inside its flex host (existing), so a long state name wraps or truncates by the host's existing rules and never squeezes the icon. On the state H1 (A1), the icon and the state name are wrapped in one inline-flex unit with the name kept whole: at phone widths the heading may wrap *before* "in", but the icon never separates from its name onto a different line.

## 4. Semantics

- **The icon is decorative on every placement in §2 — no exceptions found.** On A1–A5 the state name is always present as real text beside the icon, and the icon adds no information the text does not carry. Treatment on all five: `aria-hidden="true"`, `focusable="false"`, no `alt`, no `<title>`, no `aria-label`, no role. The name is never duplicated inside the SVG (the existing component already guarantees this; the unit test asserts no name text in the markup). Ada extended the decorative classification and her forced-colors conditions to A5 (`ADA-RULINGS-A5.md`, Rulings A5-1 and A5-3), with two composition conditions the build carries: the A5 separator dot takes A3's `aria-hidden` treatment, and DOM order is the ruled order (location, separator, outline, name).
- **No surface was found where the icon would carry meaning alone**, so no informative treatment is specified. If a future surface proposes an icon *without* the name text (a map pin, a compact table column), it is a new design requiring its own ruling — this spec does not authorize icon-only state references anywhere. The standing rule from the existing component's contract holds: **the state name must always be printed beside the shape as text.**
- **Links and chips keep their existing names.** On A2 and A4 the accessible name comes from the visible text exactly as today; an `aria-hidden` SVG contributes nothing to it, so screen-reader output is byte-identical before and after this build.
- **Forced colors:** a `currentColor` stroke follows the text color under forced-colors mode; a tinted fill would be suppressed. This is recorded for Ada's pass as a point in favor of the §2 color proposal — it is not asserted as her ruling.

## 5. Component contract for the build

### 5.1 One component, keyed by code — evolve the existing one

The build **extends `StateShape`** (`v2/components/seller/StateShape.tsx`); it does not create a second component. Contract:

- **Name:** `StateShape` (unchanged). Callers already exist at A2, A3, A4; the build adds the A1 caller in `app/state/[slug]/page.tsx` and the A5 caller in `components/variety/ListingRow.tsx` (variety context only, per Nadia's structure spec).
- **Props:** `region: string | null | undefined` — the USPS code (= `seller.region`), any case, trimmed and upper-cased inside the component (existing). `size` — **changed by this build** from a raw number to the token sizes of §6: callers pass a named size (`"inline" | "detail" | "header"`) or the existing numeric prop is retained but only ever fed token values; either way, no caller in the codebase may pass a literal that is not one of the §6 tokens. `className` passthrough (existing). The `art` variant's code is untouched by this build (its clip data changes with the geometry — §7 D6).
- **The A1 responsive step (gate amendment A6 — mechanism named):** one `StateShape` render yields both header sizes. The A1 caller passes the base size (`size={28}`, the header token's phone value) plus `className="md:size-8"`. Tailwind's `size-8` utility sets CSS `width`/`height` to 32 px at `md` and up, and CSS overrides the SVG's `width`/`height` presentation attributes, so the box steps 28 → 32 px at `md` with no second render, no media-query prop, and no component change beyond the existing `className` passthrough.
- **Stroke reconciliation (gate amendment A3):** the build implements the component's **non-scaling 1.25 px** stroke; Elena's files' 1.5-unit stroke is a **drawing-grid weight, not a build value** — it equals exactly 1.25 px at the 20 px floor size (1.5 × 20/24), which is where Ada's and Elena's legibility evidence lives, and file-level stroke attributes are discarded by the component as today. The component **gains `strokeLinecap="round"`**: Elena's files specify round caps, the shipped component sets only `strokeLinejoin="round"` (SVG's default butt cap currently applies), and NC's open Outer Banks path is exactly where cap shape shows.
- **Data:** `STATE_SHAPES: Readonly<Record<string, StateShapeData>>` in `v2/lib/data/state-paths.ts`, keyed by USPS code, each entry `{ code, slug, name, viewBox, paths }`. **This file is generated** (`v2/scripts/gen-state-paths.py` from `state-shapes/state-paths.json`); the completed set is Elena's geometry for all 31 states (one vintage, §7 D6), landed through the bridge below and that generator — `viewBox` + `paths[]`, fit by §3 — so the component and every caller are indifferent to the geometry's vintage.
- **Generator bridge (gate amendment A5 — the gate record's item A5, not placement A5):** Elena's deliverable is the `state-icons/svg/<code>.svg` files, regenerated from Census data by `state-icons/source/build_state_icons.py`. The build extracts each file's path data into `state-shapes/state-paths.json` as `{ name, viewBox: "0 0 24 24", paths: [...] }` keyed by slug — all 31 states, replacing the shipped entries wholesale per the one-vintage ruling (§7 D6) — then runs `v2/scripts/gen-state-paths.py --write` to regenerate `v2/lib/data/state-paths.ts`. Two steps, both written down: Elena's script is the set's regeneration path; the site generator is the data path. Only path data crosses — the standalone files are never inlined into a page (the component supplies `aria-hidden` and `focusable` itself).
- **Self-hosting:** outlines are inline SVG path data in the bundle. There is no `<img>`, no external file, no network request, and nothing that can 404 or hotlink.

### 5.2 Fallback — a state with no outline yet

The set is extensible and a future state **will** arrive before its outline does. The fallback is the existing behavior, now specified as the contract:

- **Render nothing.** Unknown, empty, null, or not-yet-drawn code → the component returns `null`. The state name renders alone, exactly as the 15 missing states render today.
- **No placeholder, ever.** No generic US outline, no question glyph, no empty reserved box. A wrong geography is worse than none, and a reserved empty box reads as a broken image — the two failure modes this fallback exists to avoid. Because nothing is an image, **a broken image is impossible** on this component.
- **No phantom spacing.** Hosts use flex `gap`, which applies only between rendered children; a null icon leaves no gap artifact (verified in the current A2/A3/A4 markup).
- **The one accepted consequence:** when the outline for that state later lands, the name on A2–A5 shifts right by box + gap within its own line, and chips for that state grow by the same amount. Row heights and card geometry do not change (§7). This is registered in §7.2 rather than hidden. On A5 the same fallback applies inside the segment (Nadia §3, case A-2): the segment renders with the name alone until the outline lands.

### 5.3 Adding a new state

1. Add the state's geometry through the bridge (§5.1): extract its `svg/<code>.svg` path data into `state-shapes/state-paths.json` and re-run the generator — never edit `lib/data/state-paths.ts` by hand.
2. Add the code to the expected-set list in `v2/tests/unit/seller-states.test.ts`. That test asserts the table covers *exactly* the seller states, so it fails until both the geometry and the list are updated — treat that failure as the deliberate checkpoint, not an annoyance to silence.
3. No caller changes. Every surface in §2 picks the new outline up from the table automatically.
4. Verify one seller in the new state on A2, A3, A4, A5 and its state page on A1 (§9).

### 5.4 What the build may not do

- No per-surface forks of the component, no inline one-off SVGs in page files.
- No change to the `art` variant's code, `StatePlate`, or `STATE_SCENES` (the art variant's clip *data* changes with the geometry swap — §7 D6).
- Paint is settled by Iris's ruling (`currentColor`, no fill — §2, §7 D5); geometry, props, and fallback are frozen by this spec.

- **Seller page layout:** the Location `<dl>` grid, the state link's height and tap area (`py-1` retained), the StatePlate beside it, and every other header element are unchanged.
- **State page layout:** H1 font size, line height, and margins unchanged (28/32 px box < 36/43.2 px line height); hero scene, intro, StatePlate position, seller grid, and pagination unchanged. The heading may wrap at different points on narrow phones because its content is wider — wrapping *position* is a consequence of D4, heading *height at a given wrap count* is not.

## 8. Pushback — where "everywhere" should not mean everywhere

Dustin's ruling names three surfaces — state pages, seller index, seller pages — and this spec covers all three in full (§2). Within and beyond them, my judgment, for his decision:

1. **Not in running prose (N2, N3).** The state page names its state five times; the icon belongs at the heading (A1), the page's naming moment. Icons inside sentences would break the reading line, repeat the same glyph down the page, and turn a catalogue into a sticker sheet. If Dustin wants more presence on the state page than the H1, the honest lever is a larger H1 icon — not prose icons.
2. **Not in the breadcrumb (N1).** It duplicates the H1 directly below it and would require special-casing a shared component used on every page. Two identical icons stacked within a screenful is noise, not wayfinding.
3. **Not where the name is not actually rendered (N4, N7, N8, N11).** Several surfaces that *look* like state naming render a free-text location ("Clinton, SC") or a raw code ("SC") instead. An icon keyed by code cannot accompany text it cannot parse, and bolting one onto a code or a free-text string would decorate data the directory does not stand behind. The structured name — with its icon — is always present on those journeys (A3, A4). **Supersession, recorded:** the variety page's listing cards were this item's one open case (former N5), and this pushback was correct when written. Dustin ruled them **in** on 2026-11-22, and Nadia supplied exactly the structure change this item named as the precondition — the subline now renders the seller's state as structured data (`SPEC-LISTING-CARD.md`) — so the placement is folded in as **A5** (§1, §2, §7 D7). The icon is not bolted onto the free-text string; the condition this pushback named is the condition that was met.
4. **Not in the Add Your Farm picker (N6).** A native select cannot hold icons; replacing it with a custom 50-state listbox to satisfy "everywhere" would cost keyboard and screen-reader quality on a form whose job is completion. The picker is a control, not a naming surface.
5. **Not in admin (N7–N11).** No admin surface renders a state name as structured data — admin shows codes and verbatim submissions in a working tool Dustin uses on iPad. Decorating verbatim submission data (N9) would misrepresent it. The conditional admin token (§2) is recorded so that *if* an admin surface ever renders a name, the placement is already decided — but this build adds nothing in admin.
6. **One caution on the H1 (A1), stated plainly:** placing the icon *inside* the heading, before the name, makes the heading read "Seed sellers in [Oregon shape] Oregon." That is the commission's "beside the name" taken literally, and I recommend it over the alternative (icon before the whole heading), because the icon belongs to the state, not to the sentence. If Dustin prefers the whole-heading placement, it is a one-line change to A1 and nothing else in this spec moves.
