# State Outline Icons — Accessibility Rulings, Extension to A5 (Variety-Page Listing Cards)

**Seat:** Ada, Accessibility — owner of the WCAG 2.2 AA floor · **Date:** 2026-11-22
**Extends:** `ADA-RULINGS-SI.md` (Rulings 1–5 on surfaces A1–A4). This document rules only on the new surface **A5**; it does not restate, amend, or reopen any ruling on A1–A4 except where it says so.
**Inputs ruled on:** Nadia's structure spec for A5 (`SPEC-LISTING-CARD.md`, on main at `2cec22d`) — a structured state segment, "· [outline] {State name}", added to the Quiet Ledger listing card's subline in variety context (`v2/components/variety/ListingRow.tsx`), keyed off `seller.region` through `stateByCode()` under A3's guard, the free-text location segment kept verbatim ahead of it, absence rendering nothing; the current code of `ListingRow.tsx`, `SellerCard.tsx` (A3), and `StateShape.tsx`, read on `origin/main`.
**Method:** same footing as `ADA-RULINGS-SI.md` — WCAG 2.2 criteria named per ruling, contrast figures taken from that document's computed record and the token record in `v2/app/globals.css`, DOM/reading-order analysis from the actual markup patterns of A3 (flex host) and A5 (plain `<p>` host).
**Conformance language:** these rulings are engineering evidence against WCAG 2.2 AA, criterion by criterion. They are not certification; certification is a specialist firm testing with assistive technology, and nothing here claims it.

## Verdict in one paragraph

Ruling 1's decorative classification **extends to A5**, Ruling 3's 20 px inline floor **binds A5**, and Ruling 5's forced-colors conditions **carry to A5 unchanged in substance** — one of them (the A2 chip condition) does not transfer because A5 has no selected state, and the rest apply as written. No WCAG 2.2 AA criterion fails in Nadia's structure. The non-flex `<p>` host creates **no** accessible-name or reading-order problem — reading order follows the DOM, not the layout mode — subject to two cheap composition conditions (Ruling A5-1): the separator dot takes A3's `aria-hidden` treatment, and the segment must hold together as one unit when the line wraps. Four additional gate assertions are registered in Ruling A5-4 (absence silence, 320 px / 200 % behaviour of the two-segment line, text-spacing survival, and name-diff identity).

## Ruling A5-1 — Decorative classification: EXTENDED to A5

**Ruling 1 extends.** The outline on A5 is decorative, on the fact pattern Ruling 1 requires, which Nadia's spec reproduces exactly: the state name is present as genuine text immediately beside the outline, and the outline adds no information the text does not carry. Treatment is inherited unchanged from the `StateShape` contract and Mina §4: `aria-hidden="true"`, `focusable="false"`, no `alt`, no `<title>`, no `aria-label`, no role. Criterion 1.1.1 (Non-text Content) is satisfied the same way as on A1–A4: assistive technology can ignore the graphic completely, and must be able to.

**The composition questions, answered in turn:**

- **Accessible name — no issue, and A5 is the simplest case in the set.** A2 put the icon inside a control and A4 inside a link; A5's segment sits in a plain subline paragraph that is neither. The paragraph has no accessible name to corrupt — it is text content, read as text. The card's naming machinery is elsewhere and untouched: the heading link inside the `<h3>` takes its name from the seller's name alone, and the `<article>`'s `aria-labelledby` points at that heading. An `aria-hidden` SVG contributes nothing to either, so both are byte-identical before and after the build — which is why Nadia's §6 name-diff check is the right gate assertion and is adopted into Ruling A5-4 below.
- **Reading order — no issue, and the non-flex host is why.** Reading order under 1.3.1 / 1.3.2 follows the DOM, not the layout mode. A3's host is a flex `<p>`, where a reordering property (`order`, reverse directions) *could* in principle divorce visual order from DOM order; A5's host is a plain `<p>` in normal inline flow, where no such divergence is possible — the location segment, separator, outline, and state name are encountered by sighted readers, magnifier users panning the line, and screen readers in exactly the DOM order Nadia specifies, which is also the meaningful order. The segment introduces no new reading stop: it is a continuation of the same sentence-line, not a heading, link, list item, or region.
- **The state name is announced once.** It is read a single time, as the subline's own text, in place. The C1 duplication Nadia prices ("Clinton, SC · South Carolina") is a duplication of *content* between two honestly-sourced text segments — the seller's verbatim words and the directory's filed state — not a double announcement caused by the graphic; the SVG announces nothing. That composition is Nadia's and Dustin's call, already gated on A3; this seat records only that it creates no 1.1.1 or 1.3.1 defect.
- **The segment is not interactive and must stay that way.** It carries no link, no target, and no tab stop (the card's state door remains A4, reached via the seller page, as Nadia §5.3 states). 2.4.3 (Focus Order) and 2.5.8 (Target Size) are untouched. `focusable="false"` on the SVG is part of keeping this true in legacy engines.

**Two composition conditions** (both cheap, both already the A3 pattern — stated here so the build does not improvise past them):

1. **The separator dot takes A3's treatment: `aria-hidden="true"`.** On A3 the "·" is an `aria-hidden` span, so the announced line reads as continuous prose. If A5 renders the dot as bare text, some screen readers announce "middle dot" mid-line — a new announcement A3 does not make, and an inconsistency between two cards showing the same seller. With the dot hidden from AT, the announced subline is the location text followed by the state name, uninterrupted. Visually the dot remains, doing its separating work for sighted readers.
2. **DOM order is the ruled order.** Location segment first, then separator, outline, name — in markup as in Nadia §1.1, including case C2 (no location string), where the segment stands alone with **no leading separator** and the name is simply the line's text. No markup trick (visually repositioned spans, CSS-generated separators carrying meaning) may substitute; a separator inserted by CSS `content` would be inconsistently announced across AT and is not the A3 pattern.

**Boundary of this extension, same as Ruling 1's:** it holds only while the name text is present. Nadia's structure guarantees this — segment 2 exists only as outline + name together, or name alone under her §3 case A-2 — and the guarantee is a condition of this ruling. An outline without its name on A5 would stop being decoration and would reopen Rulings 1 and 2 for this surface.

## Ruling A5-2 — The Ruling 3 floor: BINDS A5 at 20 px

**The 20 px inline floor binds A5, stated as it applies here: no state outline on a variety-page listing card may render in a box smaller than 20 px, for any state.** The flagged five of Ruling 3 (WA, NC, ME, NY, FL) and the wide-state ribbon arithmetic (NC ≈ 6.7 px tall in a 20 px box, less below it) were established from Elena's renders at the floor size; that evidence is size evidence, not surface evidence — a glyph that has collapsed at 18 px on A3 has collapsed at 18 px on A5. Nothing about the listing card changes the geometry of the glyph.

**How the floor sits on this host line.** A5's host is `text-base` (16 px text), one step larger than A3's `text-sm` line, on which the 20 px box already fits — Ruling 3 recorded the fit there as 20 px box inside a 21 px line height, the tightest figure in the SI build. The listing subline's line box is larger than A3's, so the floor is *easier* to satisfy here, not harder; the expected implementation — Mina's candidate, the existing `--size-state-icon-inline` token at its ruled 20 px value — satisfies this ruling on its face. Two clarifications so the floor is not misread in either direction:

- **The floor is a minimum, not a proportion.** The larger host line is not an argument for a larger box from this seat: 20 px is where the set's legibility evidence holds, and any size Mina chooses at or above it is her placement call, provided the box-to-line fit she measures keeps the card's geometry as Nadia §4 requires. Conversely, the floor does not shrink to fit a line: if Mina's box-to-line measurement on this line were ever to come back against the 20 px box, the resolution is in the line or the placement — never a sub-20 px outline. (On the recorded figures that conflict does not arise; her measurement is still required, per Nadia §7.1, because unmeasured is not passed.)
- **Classification is unchanged from Ruling 3.** This is a binding legibility condition from this seat on professional-practice grounds, not a WCAG criterion failure: no criterion sets a minimum size for a decorative graphic, and the name text carries the information at any size. Quinn's gate should treat it as blocking, labeled as what it is — exactly as on A2/A3.

The non-scaling 1.25 px stroke of the set applies on A5 as on every inline placement; a thinner scaled stroke at this size would undercut the same evidence.

**Contrast, priced for completeness** (Ruling 2's logic, extended without new computation): 1.4.11 does not bind a decorative mark, per Ruling 2. If the outline were treated as meaningful, its expected paint is `currentColor` from the subline's own `muted` — the identical pairing Ruling 2 already computed for A3 (muted on surface 6.14:1, pass against 3:1). A5 adds one ground A3 does not have: the sold-out card steps down from surface to paper, where the token record puts muted at 5.6:1 — still a pass against 3:1, and the host *text* itself passes 1.4.3 (4.5:1) on both of the card's grounds, so the subline's legibility is unchanged with or without the segment. The sage prohibition of Ruling 2 applies on A5 as everywhere: sage (2.74:1) must never paint these marks. Iris has since extended her paint ruling to A5 (`IRIS-COLOR-A5.md`, `459f443`) on exactly the pairing priced here — `currentColor` → muted, no fill — so the priced pairing is now the ruled pairing; the floor verdict in this paragraph is this seat's, as hers defers it.

## Ruling A5-3 — Forced colors: standing conditions CARRY to A5, with one non-transfer recorded

**Confirmed: Ruling 5 carries to A5.** The mechanism is the same one Ruling 5 confirmed — a `currentColor` stroke with no fill follows the host text's color when the operating system replaces the palette, so the outline remains visible as a mark in the subline, painted in the user's system text color, and its total disappearance (which no conforming implementation produces) would still cost no information because the mark is decorative (Ruling A5-1). A5 in fact presents the cleanest forced-colors case in the set: the whole subline is one color of plain text, the segment is distinguished from the location segment by its separator, its position, and its words — **state on this card never rests on color at all**, so 1.4.1 (Use of Color) has nothing to lose when the palette is stripped.

The standing conditions, as they apply here:

1. **No `forced-color-adjust: none`** — on the outline, on the segment, or on the subline/card hosts. The exemption stays reserved for true color specimens. This condition transfers verbatim.
2. **State must not rest on color alone** — satisfied structurally on A5, per the paragraph above; the gate verifies it by viewing the card in forced colors and confirming the state segment is still findable as text (it is the state *name*, in system text color), not by checking the outline's hue.
3. **Recorded non-transfer:** Ruling 5's second condition — the A2 chip's selected state must not rest on its stripped background — **does not apply to A5 and is not amended**; A5 has no selected state, no control, and no background-carried state anywhere in the segment. The card's sold-out treatment is a ground step-down whose meaning is carried by the status line's text, and it is unchanged by this build (Nadia §4). Nothing in Ruling 5 is weakened by this non-transfer; the condition simply has no object on this surface.
4. **The rendered check stays open until viewed.** Nadia's §6 forced-colors check (outline visible, following the subline's text color, in a real forced-colors environment — Windows High Contrast via Edge) is adopted as a gate requirement for A5 alongside A1–A4. This ruling is a design-level confirmation from the `currentColor` mechanism; per this seat's rule, unmeasured is not passed.

**Dependency, resolved on the record:** this confirmation rests on the `currentColor` basis, which was pending Iris's extension when Nadia wrote her spec (§5.2). Iris has since ruled (`IRIS-COLOR-A5.md`, on main at `459f443`): `currentColor` → muted, no fill, extended to A5 unchanged — so the mechanism this ruling relies on is the ruled paint, and the confirmation stands on it. Had she ruled a fixed paint instead, Ruling A5-3 would have reopened automatically — the same dependency Ruling 5 itself carries on A1–A4.

## Ruling A5-4 — Additional assertions the A5 checks must make at the build gate

Beyond Nadia's §6 checks (which this seat endorses, including honest keying and its adversarial cases), the build gate must assert:

1. **Absence is silent and shapeless (extends Ruling 4).** In case A-1 (no structured state), the segment must not exist in the DOM at all — no empty span, no separator dot, no `aria-hidden` placeholder, no reserved box — and the announced subline must be identical to the pre-SI card's: the location text, or the fallback chain, and nothing else. In case A-2 (state resolves, outline not yet drawn), the name renders alone and is announced exactly once, with no gap artifact where the outline will land. The segment is static text in a static card: nothing about its presence or absence may be wired to a live region or announced dynamically — additions land between deploys, never in-session, and Ruling 4's negligible-shift assessment (horizontal only, same line, AT output identical) extends to A5's later-outline shift on exactly those terms. Condition carried from Ruling 4: outlines arrive as inline SVG in the initial HTML; a late-injected outline would reopen this paragraph.
2. **320 px / 200 % behaviour of the two-segment line (1.4.4 Resize Text, 1.4.10 Reflow).** At a 320 CSS px viewport and at 200 % text resize: the two segments wrap as ordinary text with no two-dimensional scrolling, no clipping, and no overflow of the card; the wrap point may fall between the segments or before the separator, but **the outline must not separate from its state name onto a different line** — the segment holds together as one unit (mechanism is Mina's placement pass; the assertion is this seat's), because a shape stranded at a line end reads as belonging to the line above it. The outline must not squeeze or shrink at narrow widths (fixed box, `shrink-0` behaviour as on A1–A4). Vertical growth of the card from an extra wrapped line at these settings is conforming reflow, not a geometry defect — Nadia's card-height-equality check governs at standard sizes, this paragraph governs at magnification.
3. **Text-spacing overrides survive (1.4.12).** With line height at 1.5×, letter spacing at 0.12 em, and word spacing at 0.16 em, nothing in the subline clips, overlaps, or disappears — including the outline sitting in the widened line. Fixed-height text containers are where this criterion dies; the subline must remain an ordinary flowing paragraph.
4. **Name and announcement identity, by diff (1.1.1 / 4.1.3-adjacent hygiene).** Before/after diff, not eyeball: the heading link's accessible name, the `<article>`'s `aria-labelledby` result, and the tab order of the card are identical; the subline's announced text differs from pre-SI only by the state name itself, read once, in place (plus, in case C2, by the *removal* of the raw code pair Nadia retires — an announced improvement, recorded here so the diff is expected, not flagged).
5. **The flagged five at A5.** Spot-check WA, NC, ME, NY, and FL rendered at A5 beside their A3 renders of the same sellers: the same state, recognisable by the same surviving features Ruling 3 recorded, at the same 20 px box. This is the gate-level evidence that Ruling A5-2's floor was actually built, not merely tokenised.
