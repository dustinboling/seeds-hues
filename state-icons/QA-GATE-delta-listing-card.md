## 4. Ruling on the open flag — the `text-sm` line height

Mina's flag is **upheld**. The shipped theme computes `text-sm`'s line height as `calc(1.25 / 0.875)` — a unitless ratio of 1.428571… applied to the 14 px font size gives **20 px exactly** (equivalently, 1.25 rem). `globals.css` defines no `--text-*` override, and `ListingRow`/`SellerCard` carry no additional line-height utility on these lines. The gated record's 21 px figure — which appears in Ada's Ruling 3, in my A1 amendment's §7.2 sentence, in the folded spec's §2 A3 row and §7.2 bullet, and is echoed in Ada's A5 extension — is wrong. It was wrong when I prescribed it; Mina applied it faithfully and flagged it instead of improvising, which is exactly the behavior the fold-in protocol exists to produce.

The ruling, in three parts:

1. **A1's figures STAND.** Every operative figure in amendment A1 — the 20 px token, D1's +26/+2 px, D2's +24/+2 px — is box-plus-gap arithmetic and depends on the line height in no way. Nothing about the amendment's decisions changes.
2. **The justification needs correction in the record (amendment D-1, §5).** The true statement is **20 px box in a 20 px line — equality, zero headroom**, not "20 < 21, 1 px of headroom." The protected conclusion — *the A3 location line cannot grow* — still holds, but it now holds by equality rather than by slack: in `SellerCard`'s flex host, the line's height is set by its tallest item; the text span's line box is 20 px and the segment span's height is max(20 px box, 20 px name line box) = 20 px, so the line is 20 px before and after the build. Two consequences are recorded honestly: the pre-build 18 px box had 2 px of slack in that line and the amendment consumes all of it — any future rise of the inline token breaks A3's no-growth guarantee immediately, which makes the build gate's rendered measurement of A3's line height **load-bearing rather than prudent**: any measured growth, by any amount, is a §7.2 failure, not a rounding tolerance.
3. **A5's figures are UNAFFECTED — Mina's independence claim is verified, not merely accepted.** `text-base`'s line height is `calc(1.5 / 1)` = 1.5 × 16 px = **24 px**, computed from the same `theme.css` by an independent path (different token, different ratio, no shared input with the `text-sm` figure). The A5 fit stands exactly as Mina ruled it: 20 px box = 83.3% of the 24 px line box, 4 px of slack, 2 px per side, line cannot grow. No A5 figure in any of the four package documents depends on the 21 px figure; Ada's A5 text echoes it only as a comparison ("easier than A3's"), and the comparison's direction survives the correction — A5 remains the more comfortable host.

### Minor

**m1 — The A3 line-height figure in the gated record is wrong: 21 px where the shipped theme computes 20 px.**
Object: `PLACEMENT-SPEC.md` §2 A3 row ("line height 21 px > 20 px box") and §7.2 ("20 px box < 21 px line — 1 px of headroom"); origin in Ada Ruling 3's figure as prescribed by this gate's amendment A1 in `QA-GATE-design.md` §5. Evidence: Tailwind 4.3.5 `theme.css`, `--text-sm--line-height: calc(1.25 / 0.875)`, computed in §4; `globals.css` carries no `--text-*` override. Expected: the register's headroom claim matches the shipped token. Actual: the claim overstates headroom by the whole of it — the true figure is equality, zero headroom. Impact: no design value, placement, or protected outcome changes (the no-growth conclusion holds by equality, §4.2), so this is Minor, not Major — but the build gate's pass criteria quote §7.2, and a brief written from the uncorrected text would carry a false figure into them.
**Required correction (amendment D-1, a fold-in of a computed fact — no design decision, no re-gate):** in `PLACEMENT-SPEC.md` §2 (A3 row) and §7.2, replace the 21 px figure and the "1 px of headroom" claim with the equality statement (20 px box in a 20 px line; zero headroom; the tightest figure in the build; rendered measurement at the build gate is load-bearing). Hue to note the same correction against Ada Ruling 3's and this gate's A1 text wherever they are cited; the documents of record for the build are the corrected spec and this record.

**m2 — Same defect class, one surface over: the A1 header's `md` line-height figure (43.2 px) does not match the shipped theme (40 px).**
Found by defect clustering around m1 — the neighboring line-height figures were re-computed, and the phone figure checks out (text-3xl: `calc(2.25 / 1.875)` × 30 px = 36 px, as the spec states) but the `md` figure does not: text-4xl's line height is `calc(2.5 / 2.25)` × 36 px = **40 px**, not 43.2 px (43.2 = 36 × 1.2, the base-layer heading ratio, which the `text-4xl` utility's own line height overrides). Object: `PLACEMENT-SPEC.md` §2 A1 row and §7.2 ("36/43.2 px line height"). Impact: the protected conclusion holds with more room than the m1 case — 32 px box < 40 px line, 8 px of headroom rather than the recorded 11.2 px — so this is Minor and cosmetic to the register, corrected for the same reason: gate figures must be computed from the shipped tokens, not carried from an assumed ratio.
**Required correction (amendment D-2, same status as D-1):** 43.2 px → 40 px in both places.
